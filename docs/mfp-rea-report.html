1 · What the app actually is

MyFitnessPal's website is a Next.js app (build YdrvCJAG-JMnj1tNPXRgj). It is not a monolith — the frontend is a thin client over a set of backend microservices. The Next.js /api/* routes are just proxies; the real logic lives in backend services addressed through environment-configured hosts.

4 · What this means for a clone

  • Don't clone the frontend chunk-for-chunk — clone the service boundaries. The winning structure is: thin web client → API gateway → small services (diary, foods, meal plans, billing).
  • Auth is boring on purpose — NextAuth with credentials + Facebook. Nothing custom to reverse here; use any auth library.
  • The food database is the moat, not the code. The bundles reference a /v2 food API, but the data behind it (millions of user-verified entries) isn't in the client. For a personal clone, Open Food Facts + USDA FoodData Central cover the same ground for free.
  • Premium = Stripe + feature flags. Subscriptions, portal sessions, and TruMed are all standard Stripe — the "premium" features are just gated routes, not special technology.
  • Meal plans are a separate service (MEAL_APP_HOST) — you can build diary + food search first and add meal planning later without touching the core.
